# 开始逆向前的基本知识

一般的程序，从源代码到可执行的二进制文件需要经过几个阶段，

```
源代码->预处理->编译->汇编->链接->可执行二进制文件
```

编译指的是把高级语言处理成汇编语言，也就是IDA中能看到的mov、jmp这些指令。汇编指的是把汇编语言翻译成机器码，机器码人类不可读，以二进制形式0和1存在，当然因为0和1太过繁琐，所以实际上软件显示的二进制（bin）采用的是十六进制（hex）的方式，比如0x15AB6C90。链接指的是把编译的多个文件包括外部的库文件拉进程序里，最终形成完整的程序。

那么反汇编指的就是把0101的机器码重新处理成mov、jmp这样的汇编指令，反编译就是把上一步里的mov、jmp这些汇编指令重新变成伪代码形式的高级语言，为什么是伪代码而不是源代码呢？因为编译前的预处理环节通常会把很多信息去掉，比如对于程序而言，执行一个函数是去执行函数里面的代码，那么函数名字叫什么对程序一点用也没有，程序只需要知道什么时候去执行函数里的代码就行了，因此很多用于方便人类看懂的内容通常会被去掉，IDA只能根据代码用途和导入内容大致还原出部分函数，而无法还原出完整源代码。

因为C语言又是计算机最初的高级语言，能够充分表达底层内容，比如有指针、结构体等，所以IDA选择以C伪代码的形式去反汇编（所以IDA反编译出来是C语言，不代表程序就是用C编写的哦）。


# IDA的安装和使用

首先在招新群提供了破解版的IDA9.1，有两种使用方式，一是用安装包去安装，比如windows系统是直接运行ida-pro_91_x64win.exe，安装好以后把kg_patch/windows的两个dll文件放到你安装的文件夹，idapro.hexlic也复制过去，然后启动软件，会提示你校验什么的，选择用hexlic去校验，然后密钥用keygen3.py生成的密钥，由于我已经安装并破解过了所以不好演示，大家可以自己慢慢折腾。

这里推荐更方便的方式，portable文件夹里提供了已经破解好的移动版，可以直接使用，直接运行里面的ida.exe就行。linux和mac的使用也类似，不过mac没有移动版，需要使用第一种方法手动破解。

# IDA的界面与基本操作

双击IDA启动，有个小窗口点New直接进去，然后就可以选择你要逆向的软件了。这里我们选择Task1。

![ref1](/assets/images/2026-10-18-MDTask1-for-beginner/ref1.webp)

接下来的窗口是让我们选择二进制文件的加载方式，直接OK用默认的加载方式就好，后续要加载一些比较特殊的二进制文件比如内存dump的程序代码才需要设置。

![ref2](/assets/images/2026-10-18-MDTask1-for-beginner/ref2.webp)

第三个窗口是让我们选择要不要加载DWARF调试信息，简单来说就是程序编译的时候如果选择了以debug的形式去编译，那么就会保留程序源代码的部分信息，比如真实的函数名、变量名、数据类型等，没有这些信息的话，IDA就会自己起名`sub_xxxx`这样，导入的话就可以直接显示原函数名`write_file`这样，我们默认选择就导入就行，直接YES。

![ref3](/assets/images/2026-10-18-MDTask1-for-beginner/ref3.webp)

那么就正式进入到了IDA的主界面。接下来会对几个重要的部分进行讲解。

## IDA View

首先是IDA View，这是默认打开的汇编语言窗口，默认以图的方式展示函数的执行流，自上而下跟着箭头的方向，就是程序执行的顺序，有些代码块有多个箭头代表存在if else这样的分支，我们也可以在该界面按键盘的`空格`来切换到另一种视图，

![ref4](/assets/images/2026-10-18-MDTask1-for-beginner/ref4.webp)

直接按二进制文件中的组织顺序，显示里面所有二进制码的反汇编。这种模式虽然不能直观看出执行顺序，但展示的内容更多，除了记载程序代码的text节，还展示了.bss、.rdata这种记载数据的节，一个程序可以简单的分为代码部分和数据部分，数据部分不存在执行流程，因此图的方式并不能显示这些内容，如果你在这些数据部分按空格切换到图模式，IDA就会告诉你无法切换。

![ref5](/assets/images/2026-10-18-MDTask1-for-beginner/ref5.webp)

## Functions

见上面图片的左侧窗口，函数窗口就是字面意思展示函数，双击函数就能快速跳转到对应的代码段，我们常常在这里寻找main函数（`Ctrl + F`启动搜索），main函数是大部分程序最主要的部分，因此分析也会从main函数开始分析。

## Imports

Imports窗口显示了程序从外部动态链接库导入的内容，里面的内容和函数窗口像但是实际并不一样，Imports窗口不展示程序自己编写的函数。程序运行时实际会从操作系统中导入.dll啊、.so这些外部链接库（就像写c语言时的include啊，写python时的import啊这样，有了这些外部库，程序员就不必造轮子），在后面的分析中，我们可以通过导入表快速判断程序的结构和防护手段，比如看看是否导入了一些图形化函数、反调试函数、加密函数。

![ref6](/assets/images/2026-10-18-MDTask1-for-beginner/ref6.webp)

## Strings

Strings窗口不是默认打开的，我们可以通过快捷键`shift + f12`打开，它存在的意义是帮我们快速判断程序有哪些字符串，一些CTF逆向新手题中的flag就直接能在Strings窗口看到。对于实战，这里常常记载着一些ui信息如“Invalid password”或者路径信息如“"C:\\Windows\\System32\\”，可以辅助我们判断。

![ref7](/assets/images/2026-10-18-MDTask1-for-beginner/ref7.webp)

## Pseudocode

Pseudocode窗口展示了IDA从汇编代码反编译得到的伪代码，伪代码以c语言的形式展示，相比汇编，更接近高级语言的伪代码会更适合阅读，因此可以说是最重要的窗口之一了。窗口默认不展示，需要从IDA View界面选中对应的函数，然后按快捷键`f5`进行反编译。当然，反编译是比反汇编更麻烦的操作，反编译的结果常常不一定准确，需要结合汇编窗口进行分析。有反编译干扰时，IDA也不一定能直接反编译出来。

![ref8](/assets/images/2026-10-18-MDTask1-for-beginner/ref8.webp)

# Task1题目解析

作为一道入门题，主要是想让大家学习IDA的使用，只要把main函数反编译出来，游戏就结束了，可以看到程序逻辑是检查输入的内容是否和enc数组异或0x12345678的结果相同，输入的内容最初通过scanf传给变量v4，这里的v4就是ida自己命名的变量名，v4又传给v6，最终由v6去比较，如果和enc数组异或0x12345678的结果相同，就提示正确。

```c
int __fastcall main(int argc, const char **argv, const char **envp)
{
  _BYTE v4[36]; // [rsp+20h] [rbp-30h] BYREF
  int i; // [rsp+44h] [rbp-Ch]
  _DWORD *v6; // [rsp+48h] [rbp-8h]

  _main();
  puts("please input your flag");
  scanf("%s", v4);
  v6 = v4;
  for ( i = 0; i <= 5; ++i )
  {
    if ( *v6 != (enc[i] ^ 0x12345678) )
    {
      printf("Data3rr0r!");
      exit(0);
    }
    ++v6;
  }
  printf("you are right!");
  return 0;
}
```

接下来就是去查看enc数组的内容。在伪代码窗口双击enc这个变量，就会自动跳转到汇编窗口的.data节，里面就有enc的具体内容。

![ref9](/assets/images/2026-10-18-MDTask1-for-beginner/ref9.webp)

异或是一个可以还原的操作，一个数A异或另一个数B两次就会还是这个数A。最后，把enc的内容复制出来，写成脚本去异或就能得到flag

```python
enc = [0x51670536, 0x5E4F102C, 0x7E402211, 0x7C71094B, 0x7C553F1C, 0x6F5A3816]
print(b"".join((e ^ 0x12345678).to_bytes(4, 'little') for e in enc).decode())
```

最终flag `NSSCTF{Littl3_Endiannnn}`。

最后的最后，IDA会把逆向的内容（比如你重新命名的函数名等）打包到数据库，也就是i64为结尾的文件，如果一次没逆向完，下次可以在打开IDA的界面中选择这个i64文件继续逆向。

![ref10](/assets/images/2026-10-18-MDTask1-for-beginner/ref10.webp)
