# VMP介绍

VMP本身其实是叫VMProtect，是一款由VMProtect Software开发的反逆向商业软件，在讨论技术时，通常简洁一点直接叫VMP。其核心原理是指令虚拟化，将原始的指令转换为为自定义指令，程序运行时运行虚拟机，读取并解释自定义指令。自定义指令与常见的x86、ARM指令集都完全不同，静态分析软件无法从这些指令直接反汇编，分析人员必须用尽手段去分析每一条指令的含义，去转译成我们常见的指令集，这是逆向中最大的难点。除外，VMP还用尽了几乎所有的反逆向手段，包括花指令、控制流平坦化、反调试、符号剥离、壳，下面截图来自官网vmprotect.com中的信息，VMP可以说是逆向分析者最大的挑战了。

# 相关理论

下面先来讲讲VMP是怎么实现指令虚拟化的。其实虚拟机执行指令的原理和正常CPU执行指令的原理是一样的，区别在于VMP虚拟机把一切都改得面目全非了，如下图所示，VMP虚拟机有一套自己的虚拟寄存器，化用了原来的寄存器；有一套自己的虚拟指令；还有一套虚拟机处理表，用来解释自定义的虚拟指令。

![ref2](/assets/images/2026-08-20-VMP/ref2.webp)

整个执行的流程就是，虚拟机去取指令，然后解释指令，然后操作改变对应寄存器，然后继续取下一条指令、解释、执行，直到运行完毕。

那么可以看到，整个虚拟机的核心就是`自定义指令集`与`自定义解释器`，这样才能在保护原始指令的同时，运行时把抽象的虚拟指令化为真正可以执行的指令。

虚拟机可以被抽象为一个结构体，记录虚拟机相关的寄存器等。

```c
typedef struct
{
    unsigned int r1;   // 虚拟寄存器 r1
    unsigned int r2;   // 虚拟寄存器 r2
    unsigned int ip;  // 指向正在解释的 opcode 地址
    unsigned char mem[256];    // 虚拟内存
    unsigned char code[1024];  // 存放自定义机器码
} VM;
```

## 自定义指令集

对于其中的code，自定义指令集的部分，其指令集原则跟普通的指令集原则是一样的，分为变长和定长，可以参考下图看看各个指令集的排布是怎样的，因为VMP虚拟指令也会遵循指令的基本写法，只不过把OP、RSI等全换了，比如某真实架构的mov指令本来是0x10，而VMP自己写的aaa指令是0x40，而由解释器来对aaa进行解释，当解释器读到aaa时就会去查表，然后翻译为mov（0x10），然后执行。当然VMP的指令解释关系没这么简单，aaa可能对应一套指令操作而非单条指令。

![ref3](/assets/images/2026-08-20-VMP/ref3.webp)

## 自定义解释器

自定义解释器，其实就是C里面的switch和case，根据读到的不同指令，执行不同的操作，形式如下：

```c
int vm_run(VM* vm) {
    char opcode;
    char operand_1, operand_2;

    while (1) {
        opcode = vm->code[vm->ip];
        switch (opcode) {
        case 0x10:
            operand_1 = vm->code[vm->ip + 1];
            vm->r1 = operand_1;
            vm->ip += 2;
            break;

        case 0x11:
            operand_1 = vm->code[vm->ip + 1];
            vm->r2 = operand_1;
            vm->ip += 2;
            break;

        case 0x20:
            operand_1 = vm->code[vm->ip + 1];
            operand_2 = vm->code[vm->ip + 2];
            vm->mem[operand_1] = operand_2;
            vm->ip += 3;
            break;
        }
    }
}
```

代码比较好理解的，首先取指令，然后从指令中读取操作码opcode和操作数operand，然后根据opcode，执行不同的具体操作，最后改变ip寄存器的值指向下一条指令，然后继续循环。这个解释器本质上是分发器dispatcher，属于控制流平坦化这种反逆向手段，即从IDA的程序执行流程图中，只能看到一个分发器按不同的case，进入不同的基本块，无法判断原本程序的执行流程。

题目来自南邮CTF WxyVM，main函数：

```c

  puts("input your flag:");

  v4 = strlen(&byte_604B80) == 24;
```

很经典的crackme类型，接收输入然后判断经过一番折腾后的输入和存储的某数组是否一致，重点看看sub_4005B6做了什么：

```c
__int64 sub_4005B6()
{
  __int64 result; // rax
  int i; // [rsp+0h] [rbp-10h]
  char v2; // [rsp+8h] [rbp-8h]
  unsigned int v3; // [rsp+Ch] [rbp-4h]

  for ( i = 0; i <= 14999; i += 3 )
  {
    v2 = byte_6010C0[i + 2];
    v3 = byte_6010C0[i + 1];
    switch ( byte_6010C0[i] )
    {
      case 1:
        result = byte_6010C0[i + 1];
        *(&byte_604B80 + (int)v3) += v2;
        break;
      case 2:
        result = byte_6010C0[i + 1];
        *(&byte_604B80 + (int)v3) -= v2;
        break;
      case 3:
        result = byte_6010C0[i + 1];
        *(&byte_604B80 + (int)v3) ^= v2;
        break;
      case 4:
        result = byte_6010C0[i + 1];
        *(&byte_604B80 + (int)v3) *= v2;
        break;
      case 5:
        result = byte_6010C0[i + 1];
        *(&byte_604B80 + (int)v3) ^= *(&byte_604B80 + byte_6010C0[i + 2]);
        break;
      default:
        result = v3;
        break;
    }
  }
  return result;
}
```

是一个大循环套了switch，并且从byte_6010C0的i处、i+1、i+2处读入东西，并做不同计算，那就很明显是虚拟机的形式了，此外for循环中i固定加3，说明是定长指令集，byte_604B80则是操作的区域，最后用这个区域的数据和程序原本记录的数据dword_601060比对。这里整个自定义指令集以及其操作的内容都是比较简单的，先获取出所有操作码和操作数，再用脚本还原出逻辑以后，反向推理一遍就能得出处理前的数据。
